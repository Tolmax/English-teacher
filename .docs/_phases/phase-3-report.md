## Кратко

В проекте появился MVP ИИ-помощника учителя: учитель создаёт задание для ИИ, получает сгенерированный текст, редактирует его, публикует для учеников и при необходимости скачивает DOCX. Решение встроено в текущую админку и использует существующую авторизацию, маршрутизацию, шаблоны и SQLite. Если серверный `OPENAI_API_KEY` не задан, модуль работает в mock-режиме, поэтому локально можно проверять интерфейс без реального запроса к OpenAI.

---

## Описание проблемы

До Phase 3 учитель мог вручную публиковать материалы, домашние задания, тренировки и объявления, но не мог готовить учебный материал с помощью ИИ внутри сайта. Не было отдельного хранилища ИИ-материалов, сценария генерации, ручной проверки результата, публикации для учеников и скачивания материала в DOCX.

---

## Схема решения

ИИ-помощник реализован как часть существующего `/admin`, чтобы не дублировать авторизацию, layout, меню и пользовательский сценарий учителя. Данные хранятся в SQLite в таблицах `ai_teaching_materials` и `ai_material_files`; SQL вынесен в модели. Админские контроллеры отвечают за список, создание, редактирование, генерацию, публикацию, снятие с публикации и DOCX-экспорт.

Генерация вынесена в сервис `app/services/openai-teacher-assistant.php`: при наличии `OPENAI_API_KEY` он должен использовать серверный запрос к OpenAI, а без ключа возвращает mock-материал для локальной проверки. Результат сохраняется в `generated_content` и `edited_content`; ученикам он не виден до ручной публикации учителем.

Публичная часть состоит из `/ai-materials`, `/ai-materials/{slug}` и встраивания опубликованных ИИ-материалов в блок "Материалы к уроку" на странице класса `/class/{slug}`. Для кириллических slug добавлено корректное URL-кодирование в ссылках и декодирование сегментов роутером.

DOCX-экспорт реализован без внешних библиотек через `ZipArchive`: файл собирается на лету, строки экранируются для XML, временный файл удаляется после отдачи.

Важное отклонение от полной исходной идеи из `ZADANIE_DLYA_CODEX_AI_POMOSCHNIK_UCHITELYA.md`: в Phase 3 реализован только MVP. База знаний, file search/vector store, история редакций, личный кабинет ученика, PDF-экспорт и боевое тестирование с реальным `OPENAI_API_KEY` оставлены на следующие этапы.

## Ограничения MVP

- Боевой режим с реальным `OPENAI_API_KEY` подготовлен архитектурно, но ещё не проверен на реальном ключе и реальном запросе.
- При отсутствии `OPENAI_API_KEY` генерация работает только в mock-режиме.
- Нет OpenAI file search/vector store и полноценной базы знаний.
- Нет загрузки файлов как источников для генерации ИИ.
- Нет истории редакций материала.
- Нет расширенного аудита действий.
- Нет PDF-экспорта.
- Нет отдельного кабинета ученика.
- Нет автоматической публикации без ручного подтверждения учителя.

## Риски и следующие шаги

- Настроить боевой OpenAI-режим на сервере: задать `OPENAI_API_KEY`, проверить `OPENAI_MODEL`, выполнить один реальный запрос и зафиксировать ошибки/лимиты.
- Добавить более явную подсказку в админке, что mock-текст означает отсутствие `OPENAI_API_KEY`.
- Улучшить видимость ИИ-материалов в `/admin/materials` или добавить понятное объяснение, что они управляются через `/admin/ai-materials`, но публикуются в "Материалы к уроку" у класса.
- При необходимости спланировать Phase 4: боевой OpenAI-режим, источники/файлы для генерации, улучшение промптов и контроль качества результата.
