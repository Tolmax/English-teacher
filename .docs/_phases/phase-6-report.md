# Phase 6 — База знаний для ИИ-помощника

**Дата:** 2026-06-13

---

## Что сделано

- Добавлено хранилище источников базы знаний с таблицами `ai_knowledge_sources` и `ai_material_knowledge_sources`.
- Создан админский раздел `/admin/ai-knowledge` для добавления, редактирования, архивации и восстановления источников.
- В форму ИИ-материала добавлен выбор активных источников базы знаний.
- При копировании ИИ-материала переносятся только активные неархивные источники оригинала.
- Генерация ИИ-материала теперь использует ограниченный локальный контекст выбранных источников.
- Mock-режим показывает, какие источники были учтены при генерации.
- Публичный хедер переведён на гамбургер-меню, отдельная кнопка входа учителя из шапки удалена.

---

## Кратко

После Phase 6 учитель может хранить собственные учебные источники для ИИ-помощника, прикреплять их к ИИ-материалам и использовать при генерации. Система пока не подключает OpenAI file search/vector store, но уже даёт практичный локальный fallback: выбранные активные источники превращаются в короткий безопасный контекст и добавляются в запрос OpenAI или mock-генерации.

---

## Описание проблемы

До этой фазы ИИ-помощник генерировал материалы только по полям формы: теме, классу, инструкции и заметкам учителя. У учителя не было отдельного места для учебников, конспектов, примеров и методических текстов, которые можно переиспользовать в разных заданиях и не вводить заново каждый раз.

---

## Схема решения

Решение добавлено в существующую админку без отдельного кабинета `/teacher`. На уровне БД появились таблицы источников и связей с ИИ-материалами. SQL остался в моделях, загрузка файлов вынесена в сервис, а подготовка текста для генерации вынесена в `app/services/ai-knowledge-context.php`.

Поток работы теперь такой: учитель создаёт источник в `/admin/ai-knowledge`, выбирает его в форме ИИ-материала, а при генерации контроллер `/admin/ai-materials/{id}/generate` собирает только активные неархивные источники и передаёт их в `openai-teacher-assistant.php`. Контекст ограничивается по длине, содержит название, тип, описание, теги и фрагмент `extracted_text`, а очевидные секреты маскируются перед отправкой.

От плана добавлена сопутствующая правка публичного хедера: навигация вынесена в гамбургер-меню, отдельная кнопка `button button--primary button--small` из публичной шапки удалена.

## Acceptance criteria

- [x] В БД есть таблицы `ai_knowledge_sources` и `ai_material_knowledge_sources`, схема отражена в `database/schema.sql` и `.docs/database-schema.md`.
- [x] Учитель может открыть `/admin/ai-knowledge` и увидеть список источников базы знаний.
- [x] Учитель может добавить источник базы знаний с названием, описанием, тегами и файлом или текстовым содержимым.
- [x] Загружаемый файл проходит серверную валидацию типа, размера и имени.
- [x] Учитель может редактировать метаданные источника и его текстовое содержимое.
- [x] Учитель может архивировать и восстанавливать источник без физического удаления файла.
- [x] Архивные источники не предлагаются для новых генераций.
- [x] Форма создания ИИ-материала позволяет выбрать один или несколько источников базы знаний.
- [x] Форма редактирования ИИ-материала показывает выбранные источники и позволяет изменить выбор.
- [x] Связи ИИ-материала с источниками сохраняются в `ai_material_knowledge_sources`.
- [x] Генерация ИИ-материала добавляет в prompt ограниченный локальный контекст из выбранных активных источников.
- [x] Если источник слишком большой, в запрос попадает только безопасно ограниченный фрагмент.
- [x] Mock-генерация остаётся рабочей и показывает, какие источники были учтены.
- [x] OpenAI-режим не раскрывает `OPENAI_API_KEY` и не логирует содержимое ключа.
- [x] Существующие ИИ-материалы без источников продолжают генерироваться как раньше.
- [x] Изменённые PHP/TPL-файлы проходят `php -l`.
- [x] Базовые сценарии проверены: источник -> выбор в ИИ-материале -> генерация с учётом источника.
