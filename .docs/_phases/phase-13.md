# Phase 13 — Гигачат-генерация и проверка на хостинге

## Цель фазы

Сделать ИИ-генерацию устойчивой на хостинге Timeweb: добавить Гигачат как альтернативный провайдер для генерации тестов, карточек слов и изображений для ИИ-презентаций, сохранить текущую логику для учителя и проверить полный сценарий на удалённом сайте.

Причина фазы: на Timeweb прямые запросы к OpenAI могут блокироваться по региону/IP. Это может затронуть не только генерацию картинок, но и генерацию ИИ-тестов и карточек презентаций. Поэтому нужен альтернативный провайдер, который будет работать на хостинге.

## Что входит в фазу

- Абстракция провайдера ИИ-генерации: OpenAI / Гигачат / mock.
- Настройки Гигачата через `.env`, без хранения ключей в репозитории.
- Генерация ИИ-тестов через Гигачат.
- Генерация карточек слов для презентаций через Гигачат.
- Генерация картинок для карточек слов через Гигачат.
- Понятная диагностика в админке: какой провайдер включён, задан ли ключ, доступен ли API.
- Защита от повторной поломки презентации: если карточки уже с картинками, повторная генерация не должна удалять рабочие изображения без явного действия.
- Деплой текущей версии в папку `English` на Timeweb.
- Проверка сайта и генерации на хостинге.

## Что не входит в фазу

- Личный кабинет ученика.
- Пароли для страниц классов.
- Переезд с SQLite на другую базу данных.
- Полная замена OpenAI во всех будущих сценариях вне ИИ-тестов и ИИ-презентаций.
- Сложный медиаменеджер изображений.

## Таск 1 — Провайдеры ИИ-генерации и диагностика

### Цель

Подготовить код к переключению генерации тестов, карточек презентаций и изображений между OpenAI, Гигачатом и mock-режимом.

### Нужно сделать

1. Добавить настройки в `.env.example`:
   - `AI_TEXT_PROVIDER=gigachat`
   - `AI_IMAGE_PROVIDER=gigachat`
   - `GIGACHAT_AUTH_KEY=`
   - `GIGACHAT_SCOPE=`
   - `GIGACHAT_API_URL=`
   - `GIGACHAT_TEXT_MODEL=`
   - `GIGACHAT_IMAGE_MODEL=`
2. Не хранить реальные ключи в репозитории.
3. Вынести генерацию текста и изображений в отдельные сервисы-провайдеры.
4. Сохранить mock-режим для локальной проверки без ключей.
5. Добавить диагностику в админке:
   - провайдер текстовой генерации;
   - провайдер генерации изображений;
   - задан ли ключ;
   - доступен ли API;
   - короткая понятная ошибка без показа секретов.
6. Обновить README/инструкцию по `.env`.

### Возможные файлы

- `.env.example`
- `app/services/`
- `app/services/ai-test-generator.php`
- `app/services/ai-test-provider.php`
- `app/services/ai-word-presentation-images.php`
- `app/services/gigachat-image-generator.php`
- `app/services/gigachat-text-generator.php`
- `app/services/image-generation-provider.php`
- `templates/pages/admin/diagnostics.tpl`
- `DEPLOY_TIMEWEB_INSTRUCTION.md`
- `deploy/README_DEPLOY.md`

### DoD

- Без ключа сайт не падает, а показывает понятный mock/diagnostic status.
- С заданным провайдером код выбирает правильный сервис.
- Генерация ИИ-тестов может работать через выбранный текстовый провайдер.
- Генерация карточек презентаций может работать через выбранный текстовый провайдер.
- Ошибки API не ломают страницу редактирования презентации.
- PHP-синтаксис изменённых файлов проходит `php -l`.

## Таск 2 — Гигачат для ИИ-тестов и карточек презентаций

### Цель

Научить сайт генерировать текстовые ИИ-материалы через Гигачат: стандартные ИИ-тесты и карточки слов для презентаций.

### Нужно сделать

1. Реализовать текстовую генерацию через Гигачат для ИИ-тестов.
2. Реализовать текстовую генерацию через Гигачат для карточек презентаций:
   - слово;
   - транскрипция;
   - краткая подсказка;
   - описание изображения для следующего этапа.
3. Сохранить существующие шаблоны тестов:
   - 10 вопросов;
   - два варианта ответа;
   - один правильный ответ;
   - фиксирование первой ошибки ученика.
4. Сохранить mock-режим для тестов и презентаций.
5. Если Гигачат вернул ошибку:
   - не создавать битый тест;
   - не затирать уже созданные карточки;
   - показать учителю понятное сообщение.

### Возможные файлы

- `app/services/ai-test-generator.php`
- `app/services/ai-test-templates.php`
- `app/services/ai-word-presentation-cards.php`
- `app/services/gigachat-text-generator.php`
- `app/controllers/admin/ai-materials/`
- `app/controllers/admin/ai-presentations/`
- `templates/pages/admin/ai-materials/`
- `templates/pages/admin/ai-presentations/`

### DoD

- ИИ-тест можно сгенерировать через Гигачат.
- Карточки презентации можно сгенерировать через Гигачат.
- Русская кириллица отображается корректно.
- При ошибке API не появляется битый материал в базе.
- PHP-синтаксис изменённых файлов проходит `php -l`.

## Таск 3 — Генерация картинок через Гигачат для ИИ-презентаций

### Цель

Научить ИИ-презентации получать изображения через Гигачат и вставлять их в карточки слов, HTML-просмотр и PPTX.

### Нужно сделать

1. Реализовать запрос к Гигачату для генерации изображения по английскому слову и короткому описанию.
2. Сохранять полученные изображения в `uploads/materials/{materialId}/`.
3. Использовать уже существующую структуру карточек презентации:
   - слово;
   - транскрипция;
   - подсказка/описание;
   - путь к картинке.
4. Если картинка не получена:
   - не удалять уже существующую рабочую картинку;
   - показать учителю понятное сообщение;
   - дать возможность повторить генерацию только для проблемных карточек.
5. После успешной генерации карточек показывать следующий шаг: `Собрать презентацию`.
6. После сборки PPTX показывать только:
   - `Показать`;
   - `Скачать`;
   - `Открыть в отдельном окне`.
7. Проверить, что готовая презентация не публикуется на странице класса как тест.

### Возможные файлы

- `app/controllers/admin/ai-presentations/`
- `app/models/ai-word-presentations.php`
- `app/services/ai-word-presentation-images.php`
- `app/services/presentation-builder.php`
- `templates/pages/admin/ai-presentations/`
- `templates/pages/public/presentation-show.tpl`
- `assets/css/sections/prototype-pages.css`

### DoD

- Новая презентация создаётся из английских слов.
- Для каждого слова появляется картинка.
- Повторная генерация не уничтожает уже созданные изображения.
- PPTX и HTML-просмотр показывают картинки.
- Удаление презентации удаляет папку `uploads/materials/{materialId}/` целиком.

## Таск 4 — Деплой и тестирование на Timeweb

### Цель

Залить текущую версию в папку `English` на Timeweb и проверить, что сайт работает на хостинге.

### Нужно сделать

1. Обновить папку `deploy/` только нужными файлами проекта.
2. Синхронизировать `deploy/` с папкой `English` на Timeweb.
3. Проверить `.env` на сервере:
   - `OPENAI_API_KEY`, если нужен текстовый OpenAI;
   - настройки Гигачата для тестов, карточек и картинок;
   - отсутствие лишних кавычек и пробелов.
4. Проверить права записи:
   - `database/`;
   - `uploads/`;
   - `logs/`, если используется.
5. Выполнить smoke-test на хостинге:
   - главная страница;
   - страница класса;
   - `/admin/login`;
   - `/admin/dashboard`;
   - `/admin/ai-presentations`;
   - создание ИИ-теста;
   - публикация ИИ-теста;
   - создание ИИ-презентации;
   - генерация карточек;
   - генерация картинок;
   - сборка PPTX;
   - просмотр `/presentation/{id}`;
   - удаление презентации с папкой файлов.
6. Проверить кодировку UTF-8:
   - русские тексты в админке;
   - русские сообщения ошибок;
   - названия тестов и презентаций.
7. Если API на хостинге вернул ошибку, записать её в отчёт понятным языком.

### Возможные файлы

- `deploy/`
- `DEPLOY_TIMEWEB_INSTRUCTION.md`
- `deploy/README_DEPLOY.md`
- `.docs/_phases/phase-13-report.md`

### DoD

- Сайт открывается на Timeweb.
- Админка открывается после авторизации.
- ИИ-тест создаётся через выбранный провайдер и публикуется на странице класса.
- ИИ-презентация создаётся и показывает картинки.
- PPTX скачивается.
- HTML-презентация открывается в отдельном окне и может быть показана на весь экран.
- После удаления презентации не остаётся лишняя папка в `uploads/materials`.
- В отчёте фазы указано, что проверено на хостинге и какие ограничения остались.

## Риски

- У Гигачата может отличаться формат API для генерации текста и изображений; перед реализацией нужно свериться с актуальной официальной документацией.
- На Timeweb могут быть ограничения исходящих HTTPS-запросов.
- Если ключ Гигачата задан неверно, генерация должна падать мягко и не ломать уже созданные презентации.
- Нельзя выводить ключи API в шаблоны, логи и диагностические страницы.
- Нужно следить за UTF-8, потому что раньше уже была проблема с кириллицей при генерации тестов.

## Проверка фазы

Минимальная проверка после реализации:

1. Запустить локально `php -S 127.0.0.1:8000`.
2. Открыть `/admin/login` и войти в админку.
3. Создать ИИ-презентацию из 3-5 английских слов.
4. Сгенерировать карточки и убедиться, что картинки появились.
5. Собрать презентацию.
6. Открыть презентацию в браузере и скачать PPTX.
7. Удалить презентацию и проверить, что папка в `uploads/materials` удалена.
8. Создать ИИ-тест через выбранный провайдер.
9. Опубликовать тест и пройти его на странице класса.
10. Задеплоить на Timeweb.
11. Повторить сценарий на хостинге.
