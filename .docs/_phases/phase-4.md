# Phase 4 — Боевой OpenAI-режим ИИ-помощника

## Цель

Учитель сможет запускать реальную генерацию ИИ-материала через OpenAI API вместо mock-ответа, а админка будет понятно показывать текущий режим работы и ошибки настройки.

## Порядок реализации

- **Таск 1 — Диагностика режима ИИ:** показать в админке текущий режим генерации, объяснить mock-режим при отсутствии `OPENAI_API_KEY`, добавить понятные подсказки без раскрытия ключа.
- **Таск 2 — Боевой запрос OpenAI и обработка ошибок:** проверить и доработать серверный запрос к OpenAI, обработать ошибки ключа, сети, лимитов, пустого ответа и некорректного JSON.
- **Таск 3 — Проверка боевого сценария и документация:** выполнить ручной сценарий реальной генерации, обновить README/статус и зафиксировать, как включать боевой режим на сервере.

## Статус выполнения

- [x] Таск 1 — Диагностика режима ИИ.
- [x] Таск 2 — Боевой запрос OpenAI и обработка ошибок.
- [x] Таск 3 — Проверка подключения и документация.

Ограничение Task 3: реальный запрос дошёл до OpenAI API, но успешная генерация материала пока не подтверждена, потому что OpenAI вернул ошибку лимита запросов или баланса. После настройки биллинга/лимитов нужно повторить генерацию и проверить сохранение успешного ответа.

## Публичная часть

| Маршрут | Описание |
|---------|----------|
| `/ai-materials` | Показывает опубликованные ИИ-материалы; поведение не меняется. |
| `/ai-materials/{slug}` | Показывает один опубликованный ИИ-материал; поведение не меняется. |
| `/class/{slug}` | Показывает опубликованные ИИ-материалы в блоке "Материалы к уроку"; поведение не меняется. |

## Админка

| Маршрут | Описание |
|---------|----------|
| `/admin/ai-materials` | Список ИИ-материалов и понятный индикатор режима: mock или OpenAI API. |
| `/admin/ai-materials/create` | Создание черновика ИИ-материала; форма не должна раскрывать API-ключ. |
| `/admin/ai-materials/{id}/edit` | Редактирование материала, запуск генерации, отображение статуса режима и ошибок генерации. |
| `/admin/ai-materials/{id}/generate` | POST-запуск генерации через OpenAI API или mock-режим. |

## Прототипы

**Страницы:**
- Отдельного прототипа для ИИ-помощника нет.
- `prototypes/admin/classes.html` → ориентир для админских списков.
- `prototypes/admin/submissions.html` → ориентир для таблиц, статусов и служебных сообщений.
- `prototypes/design-system/ui-design-system.html` → ориентир для alert, badge, card, form и button.

Вёрстку, CSS-классы и структуру разметки брать из существующих админских шаблонов и дизайн-системы. Не создавать отдельный teacher-layout.

**Assets:**
- CSS уже подключается через `assets/css/main.css`.
- Основные CSS-блоки: `assets/css/blocks/alert.css`, `badge.css`, `button.css`, `card.css`, `input.css`, `table.css`.
- Секции админки используют существующий `assets/css/sections/prototype-pages.css`.
- JS-модули лежат в `assets/js/modules/`; новый JS добавлять только если без него нельзя сделать понятную диагностику.

## Что НЕ входит в фазу

- Не создавать отдельный кабинет `/teacher`.
- Не менять публичный дизайн сайта.
- Не менять логику ручной публикации: ИИ не публикует материалы автоматически.
- Не добавлять OpenAI file search/vector store.
- Не добавлять загрузку файлов как источников для генерации.
- Не добавлять историю редакций материала.
- Не добавлять личный кабинет ученика.
- Не хранить и не показывать `OPENAI_API_KEY` в БД, браузере, логах или документации.
- Не добавлять новые внешние библиотеки и CDN.

## Важные правила

- Следовать `AGENTS.md`.
- Следовать `.docs/architecture-rules.md`.
- Следовать `.docs/specs/` для PHP, HTML, CSS и JS.
- SQL только в models, логика не в шаблонах.
- Все OpenAI-запросы выполнять только на сервере.
- `OPENAI_API_KEY` читать только из серверного окружения.
- В админке показывать только факт настройки ключа, но не сам ключ.
- При отсутствии ключа сохранять mock-режим, чтобы локальная разработка не ломалась.
- Не трогать файлы вне раздела "Файлы для создания или изменения" без явной необходимости.

## Definition of Done

- [ ] В `/admin/ai-materials` видно, какой режим активен: mock или OpenAI API.
- [ ] Учитель видит понятное объяснение, что mock-текст появляется из-за отсутствия `OPENAI_API_KEY`.
- [ ] При наличии `OPENAI_API_KEY` генерация выполняет реальный серверный запрос к OpenAI.
- [ ] Модель берётся из `OPENAI_MODEL`, а при отсутствии переменной используется безопасное значение по умолчанию.
- [ ] API-ключ не выводится в HTML, не сохраняется в БД и не попадает в пользовательские ошибки.
- [ ] Ошибка неверного ключа, сетевой сбой, лимит API и пустой ответ показываются учителю понятным сообщением.
- [ ] Успешный ответ сохраняется в `generated_content`, `edited_content`, `model_used` и при наличии `openai_response_id`.
- [ ] Неуспешная генерация сохраняет понятный `generation_error` и не затирает последний отредактированный материал.
- [ ] Mock-режим продолжает работать без `OPENAI_API_KEY`.
- [ ] Ручной сценарий проверен: создать материал → сгенерировать через реальный API → отредактировать → опубликовать → увидеть в классе.
- [ ] Изменённые PHP/TPL-файлы проходят `php -l`.
- [ ] `AI_TEACHER_ASSISTANT_README.md` объясняет, как включить боевой режим.
- [ ] `.docs/project-status.md` обновлён после завершения задач фазы.
