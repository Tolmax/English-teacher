# Phase 1 — MVP учебного сайта

**Дата:** 2026-06-11

---

## Что сделано

- Создана SQLite-схема MVP с таблицами для пользователей, классов, материалов, тренировок, вопросов и отправленных результатов.
- Реализована базовая админка учителя: вход, сводка, управление классами, управление материалами и просмотр ответов учеников.
- Реализована публичная главная страница с выбором активного класса из базы данных.
- Реализована публичная страница класса `/class/{slug}` с домашкой, материалами, объявлениями, тренировками и формой вопроса учителю.
- Реализована страница тренировки `/practice/{id}` с проверкой ответов и сохранением результата в `submissions`.
- Обновлена визуальная основа: Roboto как основной шрифт и светлая декоративная подложка с сине-красными акцентами.

---

## Кратко

После Phase 1 проект стал рабочим MVP учебного сайта учителя английского. Учитель может войти в админку, создать классы и материалы, увидеть вопросы и результаты учеников. Ученик может открыть главную страницу, выбрать свой класс, посмотреть домашку и материалы, пройти тренировку и отправить результат учителю.

---

## Описание проблемы

До этой фазы в проекте были продуктовые документы, дизайн-направление и HTML-прототипы, но не было рабочей связки сайта с базой данных. Учитель не мог публиковать классы и материалы через админку, ученики не могли открыть страницу своего класса, задать вопрос или отправить результат тренировки так, чтобы он сохранился и стал виден учителю.

---

## Схема решения

Решение собрано в существующей MVC-структуре проекта без фреймворков. В `database/schema.sql` добавлена SQLite-схема и сидовые данные. В `app/models/` вынесены SQL-запросы для классов, материалов, тренировок, вопросов и отправок. В `app/controllers/` добавлены публичные маршруты `/`, `/class/{slug}`, `/practice/{id}` и защищённые админские действия. Валидация POST-данных вынесена в `app/validators/`, а шаблоны `.tpl` используют разметку и BEM-классы прототипов. POST-действия завершаются `redirectTo()` по PRG-паттерну.

От первоначального плана есть небольшое практическое отклонение: вместо отдельного `practice/submit.php` отправка результата реализована в `app/controllers/practice/show.php`, потому что форма тренировки и обработка относятся к одному публичному маршруту `/practice/{id}`. Также добавлены partials, страница 404 и CSS-правки по файлу `.docs/_phases/ohase-1-fix.md`.

- [x] Учитель видит dashboard со сводкой по классам и последним ответам учеников.

- [x] Страница `/practice/{id}` показывает вопросы тренировки.
- [x] Ученик может отправить результат тренировки с именем.
- [x] Отправленный результат сохраняется в `submissions`.
- [x] Учитель видит отправленные результаты на `/admin/submissions`.
- [x] Проверены основные сценарии локальными командами: рендер публичных страниц, POST вопроса, POST результата, рендер админки ответов.
- [x] После реализации обновлены `.docs/database-schema.md` и `database/schema.sql`.

## Проверки

- `php -l` по PHP и `.tpl` файлам — без синтаксических ошибок.
- SQLite-схема применена к `database/database.sqlite`.
- HTTP-проверки локального сервера: `/`, `/class/7b`, `/practice/1`, `/admin/login` отвечали `200`.
- POST формы вопроса сохранял запись в `student_questions`; тестовая запись удалена.
- POST формы тренировки сохранял запись в `submissions`; тестовая запись удалена.

- Закрытый доступ к страницам классов.
- Загрузка файлов учителем.
- Архив всех прошлых домашних заданий.
- Полноценная запись на дополнительные занятия.
- Расширенная статистика успеваемости.
- Email-уведомления и внешние интеграции.
- Rich-text редактор на Editor.js.
