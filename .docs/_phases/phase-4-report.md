# Phase 4 — Боевой OpenAI-режим ИИ-помощника

**Дата:** 2026-06-13

---

## Что сделано

- В админке добавлена диагностика текущего режима генерации: mock или OpenAI API.
- Серверный OpenAI-запрос усилен: модель берётся из `OPENAI_MODEL`, ключ только из серверного окружения.
- Добавлена безопасная обработка ошибок OpenAI API: неверный ключ, недоступная модель, сетевой сбой, лимиты, пустой или некорректный ответ.
- Mock-режим сохранён как рабочий fallback без `OPENAI_API_KEY`.
- Документация объясняет, как подключить `OPENAI_API_KEY`, почему Live Server не подходит и как запускать PHP-сервер для проверки.
- Реальный запрос был доведён до OpenAI API, но успешная генерация отложена из-за лимита запросов или баланса OpenAI Platform.

---

## Кратко

Phase 4 перевела ИИ-помощника из чисто mock-сценария к боевому серверному подключению OpenAI API. Учитель теперь видит в админке, какой режим активен, а при ошибках получает понятное сообщение без раскрытия ключа. Реальный API-ключ был подключён через окружение, сервер его увидел, запрос дошёл до OpenAI, но успешный ответ требует решить внешний вопрос с балансом или лимитами OpenAI Platform.

---

## Описание проблемы

До этой фазы ИИ-помощник мог создавать тестовый mock-материал, но учитель не понимал, почему реальная генерация не включается, видит ли сервер ключ и что именно пошло не так при запросе к OpenAI. Также не было зафиксированной инструкции, как безопасно подключить `OPENAI_API_KEY` без вывода ключа в браузер или сохранения в БД.

---

## Схема решения

Реализация осталась внутри существующего раздела `/admin/ai-materials`. Сервис `openai-teacher-assistant.php` стал единой точкой генерации: если `OPENAI_API_KEY` пустой, используется mock-режим; если ключ есть, выполняется серверный запрос к OpenAI Responses API. Контроллер генерации сохраняет успешный результат в поля материала, а при ошибке сохраняет понятное сообщение в `generation_error`, не затирая последний отредактированный материал.

В шаблонах админки добавлен индикатор режима и подсказки для учителя. Документация описывает запуск через `php -S`, настройку переменных окружения, отличие от Live Server и типовые ошибки. От первоначального плана есть одно внешнее ограничение: успешная боевая генерация не подтверждена из-за ответа OpenAI о лимите запросов или балансе.

## Acceptance criteria

- [x] В `/admin/ai-materials` видно, какой режим активен: mock или OpenAI API.
- [x] Учитель видит понятное объяснение, что mock-текст появляется из-за отсутствия `OPENAI_API_KEY`.
- [x] При наличии `OPENAI_API_KEY` генерация выполняет реальный серверный запрос к OpenAI.
- [x] Модель берётся из `OPENAI_MODEL`, а при отсутствии переменной используется безопасное значение по умолчанию.
- [x] API-ключ не выводится в HTML, не сохраняется в БД и не попадает в пользовательские ошибки.
- [x] Ошибка неверного ключа, сетевой сбой, лимит API и пустой ответ показываются учителю понятным сообщением.
- [x] Успешный ответ сохраняется в `generated_content`, `edited_content`, `model_used` и при наличии `openai_response_id`.
- [x] Неуспешная генерация сохраняет понятный `generation_error` и не затирает последний отредактированный материал.
- [x] Mock-режим продолжает работать без `OPENAI_API_KEY`.
- [ ] Ручной сценарий с успешной генерацией через реальный API полностью пройден — отложено из-за лимита запросов или баланса OpenAI Platform.
- [x] Изменённые PHP/TPL-файлы проходят `php -l`.
- [x] `AI_TEACHER_ASSISTANT_README.md` объясняет, как включить боевой режим.
- [x] `.docs/project-status.md` обновлён после завершения задач фазы.
