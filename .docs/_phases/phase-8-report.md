# Phase 8 — Мобильная адаптация и визуальная полировка публичных страниц

**Дата:** 2026-06-13

---

## Что сделано

- Исправлены мобильные overflow-проблемы публичных страниц: hero-блоки, карточки, кнопки, списки материалов и длинные названия больше не должны расширять страницу.
- Убран `100vw` у hero-блока страницы класса и добавлены устойчивые grid/width-правила для 320-425 px.
- Добавлено подтверждение входа учителя: кнопка «Вход учителя» открывает окно «А ты точно учитель?» с фоном `assets/img/paddington-book.png`.
- Страница `/admin/login` и модальное окно входа центрированы.
- Footer на мобильных ширинах переведён в вертикальный вид, а модальные окна получили ограничение по высоте.
- Проверены доступные публичные маршруты и синтаксис изменённых PHP/JS/CSS-файлов.

---

## Кратко

Phase 8 довела публичную часть сайта до более аккуратного мобильного состояния. Страницы стали устойчивее к узким экранам, длинным названиям файлов и карточкам с разным содержимым. Вход учителя теперь не ведёт сразу в админку, а сначала показывает дружелюбное подтверждение с Paddington. Дополнительно центрирована страница `/admin/login` и отполирован footer на мобильных устройствах.

---

## Описание проблемы

До фазы публичные страницы могли давать горизонтальный скролл и визуально сжимать блоки на мобильных ширинах. На странице класса особенно мешал hero-блок с шириной `100vw`, из-за чего контент мог становиться шире viewport. Кнопка «Вход учителя» сразу переводила на `/admin/login`, хотя по плану Phase 8 требовалось мягкое подтверждение, чтобы ученик случайно не попадал в админский вход.

---

## Схема решения

Изменения выполнены без БД и без изменения бизнес-логики. Основной слой правок — CSS публичных блоков: контейнеры, hero, карточки, кнопки, footer, модальные окна, списки материалов и адаптивные breakpoint-правила.

В шаблоне footer добавлен native `<dialog>` для подтверждения входа учителя. Для него создан отдельный ES module `teacher-login-confirm.js`, подключённый через `assets/js/main.js`. Страница `/admin/login` получила существующие классы `login-page` и `login-card`, чтобы использовать уже заложенное центрирование.

Ограничение проверки: автоматическая браузерная проверка `scrollWidth <= innerWidth` не была выполнена, потому что in-app Browser tool и Playwright в окружении были недоступны. Вместо этого выполнены синтаксические проверки, CSS brace check и HTTP-проверка доступных маршрутов.

## Проверки

- `php -l templates/partials/footer.tpl` — успешно.
- `php -l templates/pages/admin/login.tpl` — успешно.
- ES module syntax check через `node --input-type=module --check` — успешно для `main.js`, `mobile-menu.js`, `modal.js`, `teacher-login-confirm.js`.
- CSS brace check — баланс фигурных скобок корректный в изменённых CSS-файлах.
- HTTP 200: `/`, `/class/1`, `/extra-lessons`, `/practice/1`, `/ai-materials`, `/admin/login`.
- Не проверено автоматически: `/ai-tests/{slug}` и `/ai-materials/{slug}` по реальному slug, так как в локальной БД не было доступного опубликованного теста/материала для надёжного URL.
