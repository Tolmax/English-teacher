# Phase 5 — Библиотека и архив ИИ-материалов

## Цель

Учитель сможет не удалять сгенерированные ИИ-материалы, а хранить их в удобной библиотеке, быстро находить по классу/теме/типу и переиспользовать в следующем учебном году.

## Порядок реализации

- **Таск 1 — Архив и метаданные библиотеки:** добавить/уточнить поля для учебного года, периода, тегов и архивного статуса ИИ-материала; обновить модель, схему и документацию.
- **Таск 2 — Фильтры и библиотека в админке:** улучшить `/admin/ai-materials`: фильтры по классу, теме, типу, статусу, учебному году, поиск по названию/содержанию и отдельный режим просмотра архива.
- **Таск 3 — Повторное использование материала:** добавить действие "Создать копию" для ИИ-материала, чтобы учитель мог взять прошлогодний тест/конспект, адаптировать его и опубликовать заново без потери оригинала.

## Публичная часть

| Маршрут | Описание |
|---------|----------|
| `/ai-materials` | Показывает только опубликованные материалы; архивные и черновики не отображаются. |
| `/ai-materials/{slug}` | Показывает только опубликованный материал; архивные материалы недоступны ученикам. |
| `/class/{slug}` | Показывает только актуальные опубликованные материалы выбранного класса. |

## Админка

| Маршрут | Описание |
|---------|----------|
| `/admin/ai-materials` | Библиотека ИИ-материалов с поиском, фильтрами, статусами и архивом. |
| `/admin/ai-materials/create` | Создание нового ИИ-материала с учебным годом/периодом и тегами. |
| `/admin/ai-materials/{id}/edit` | Редактирование материала, метаданных библиотеки и статуса. |
| `/admin/ai-materials/{id}/archive` | POST-действие отправки материала в архив. |
| `/admin/ai-materials/{id}/restore` | POST-действие восстановления материала из архива. |
| `/admin/ai-materials/{id}/duplicate` | GET-форма и POST-действие создания копии материала для нового класса/года/темы. |

## База данных

| Таблица | Поля |
|---------|------|
| `ai_teaching_materials` | существующие поля + `school_year`, `period`, `tags`, `archived_at`, `source_material_id` |

Новая отдельная таблица не обязательна: библиотека строится поверх существующих ИИ-материалов. Если при реализации понадобится нормализовать теги, это нужно вынести в отдельный TASK и не делать автоматически.

## Прототипы

**Страницы:**
- Отдельного прототипа библиотеки ИИ-материалов нет.
- `prototypes/admin/classes.html` → ориентир для админского списка `/admin/ai-materials`.
- `prototypes/admin/submissions.html` → ориентир для таблиц, фильтров, статусов и служебных сообщений.
- `prototypes/design-system/ui-design-system.html` → ориентир для alert, badge, card, input, table и button.

Вёрстку, CSS-классы и структуру разметки брать из существующих админских шаблонов и дизайн-системы. Если прототипа нет — не создавать новый визуальный язык.

**Assets:**
- CSS уже подключается через `assets/css/main.css`.
- Использовать существующие CSS-блоки: `assets/css/blocks/alert.css`, `badge.css`, `button.css`, `card.css`, `input.css`, `table.css`, `modal.css`, `nav.css`.
- Админские страницы продолжают использовать `assets/css/sections/prototype-pages.css`.
- JS-модули лежат в `assets/js/modules/`; новый JS добавлять только если без него нельзя сделать удобное подтверждение архивации/копирования.

## Что НЕ входит в фазу

- Не удалять материалы физически как основной сценарий: вместо этого использовать архив.
- Не добавлять базу знаний, загрузку учебников и file search/vector store.
- Не добавлять загрузку файлов как источников для генерации.
- Не делать PDF-экспорт.
- Не добавлять историю редакций каждой правки.
- Не создавать отдельный кабинет `/teacher`.
- Не менять публичный дизайн сайта.
- Не открывать архивные материалы ученикам.
- Не хранить и не показывать `OPENAI_API_KEY` в БД, браузере, логах или документации.
- Не добавлять внешние библиотеки, SDK или CDN.

## Важные правила

- Следовать `AGENTS.md`.
- Следовать `.docs/architecture-rules.md`.
- Следовать `.docs/specs/` для PHP, HTML, CSS и JS.
- SQL только в models, логика не в templates.
- Архивация не должна удалять `generated_content` и `edited_content`.
- Копирование материала не должно менять оригинал.
- Копия должна получать новый уникальный `slug`, статус `draft` или `ready`, пустые `published_at` и `archived_at`.
- Архивные материалы не должны попадать в публичные выборки `/ai-materials` и `/class/{slug}`.
- DOCX-экспорт существующих материалов должен продолжить работать.
- Mock/OpenAI-генерация не должна сломаться.
