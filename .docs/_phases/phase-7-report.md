# Phase 7 — Календарь, умная база знаний, интерактивные тесты и статистика

**Дата:** 2026-06-13

---

## Что сделано

- Добавлен календарь уроков, дедлайнов и допзанятий с управлением в `/admin/calendar` и публичным выводом событий.
- База знаний ИИ-помощника получила категории, расширенный поиск, просмотр содержимого источника и 10 тестовых источников.
- Добавлены интерактивные ИИ-тесты: создание из ИИ-материала, редактирование вопросов, публикация и прохождение учениками.
- Результаты интерактивных ИИ-тестов сохраняются в БД и доступны для статистики учителя.
- Добавлена страница `/admin/stats` со сводкой по классам, материалам, тренировкам, ИИ-тестам, вопросам, заявкам и событиям.
- Страницы классов доработаны визуально: hero-блок очищен от лишних элементов, добавлен Paddington Hello, убраны breadcrumbs и исправлена мобильная адаптация.
- Личный кабинет ученика, пароли для классов и тяжёлая персональная аналитика сознательно не добавлялись.

---

## Кратко

После Phase 7 сайт стал рабочим учебным центром: учитель может планировать события, хранить и искать учебные источники для ИИ, превращать ИИ-материалы в интерактивные тесты и видеть общую статистику активности учеников. Публичные страницы классов остались открытыми без логина и пароля, но стали богаче: на них отображаются события, материалы, тренировки и опубликованные ИИ-тесты.

---

## Описание проблемы

До этой фазы учитель мог публиковать материалы и тренировки, но не было единого календаря занятий и дедлайнов, база знаний была менее удобной для повторного использования, ИИ-материалы не превращались в полноценные интерактивные тесты, а активность учеников приходилось смотреть по разным разделам админки. Также не хватало компактной сводки, которая показывает, какие классы работают активнее и что требует внимания прямо сейчас.

---

## Схема решения

Решение добавлено внутри существующей MVC-структуры без отдельного кабинета ученика и без новых JS-фреймворков. Для календаря, категорий базы знаний, интерактивных тестов и статистики используются отдельные модели, контроллеры и `.tpl`-шаблоны. SQL остался в `app/models/`, защищённые страницы подключены через существующий `/admin`-роутер и `requireAuth()`, публичные маршруты остались открытыми.

На уровне БД добавлены или расширены таблицы `calendar_events`, `ai_knowledge_categories`, `ai_interactive_tests`, `ai_test_questions`, `ai_test_options` и `ai_test_submissions`. Для статистики отдельные таблицы не понадобились: сводка собирается из существующих данных по классам, материалам, тренировкам, ИИ-тестам, вопросам, заявкам и календарю.

От первоначального плана сознательно не делались личный доступ ученика, пароли для страниц классов, drag-and-drop календарь, внешние календарные сервисы и OpenAI vector store как обязательный сценарий. Дополнительно по ходу фазы были внесены визуальные правки публичной части: hamburger-меню, обновлённый hero страниц классов, удаление breadcrumbs и исправление мобильных переполнений.

## Acceptance criteria

- [x] Учитель может открыть `/admin/calendar`, создать урок, дедлайн или событие допзанятий и увидеть его в списке.
- [x] Опубликованные события отображаются на главной и на странице нужного класса.
- [x] База знаний поддерживает категории, фильтр по категории и поиск по названию, тегам, описанию и тексту источника.
- [x] Учитель может открыть страницу просмотра источника `/admin/ai-knowledge/{id}` и прочитать его содержимое.
- [x] Учитель может создать интерактивный тест из ИИ-материала, отредактировать вопросы и варианты ответов.
- [x] Опубликованный тест открывается на публичном маршруте `/ai-tests/{slug}`.
- [x] Ученик может пройти опубликованный тест, отправить имя и ответы, а результат сохраняется в БД.
- [x] Учитель видит отправленные результаты интерактивных тестов в статистике.
- [x] `/admin/stats` показывает сводку по классам, материалам, тренировкам, ИИ-тестам и заявкам на допзанятия.
- [x] Публичные страницы классов остаются открытыми без логина и пароля.
- [x] Изменённые PHP/TPL-файлы проходят `php -l`.
- [x] `database/schema.sql` и `.docs/database-schema.md` обновлены после изменений БД.
