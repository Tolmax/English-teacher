# Phase 3 — ИИ-помощник учителя в админке

## Цель

Учитель сможет в существующей админке `/admin` создать учебный материал с помощью ИИ, отредактировать результат, сохранить черновик, вручную опубликовать материал для учеников и скачать его как DOCX.

## Основание

Фаза основана на задании `ZADANIE_DLYA_CODEX_AI_POMOSCHNIK_UCHITELYA.md`.

Задание понятно, но его полная версия очень объёмная. В Phase 3 берём **MVP по приоритету 1** и адаптируем его под текущий проект.

Главное архитектурное решение: **не создавать отдельный кабинет `/teacher/...`**. ИИ-помощник встраивается в уже существующую админку `/admin`, чтобы не дублировать авторизацию, меню, layout, стили, маршрутизацию и пользовательский сценарий учителя.

Используем уже готовое:
- текущий вход учителя в `/admin/login`;
- существующий `admin-header.tpl` и меню админки;
- текущий роутинг через `app/controllers/admin/_router.php`;
- SQLite и модели проекта;
- существующие CSS-классы форм, таблиц, карточек и статусов;
- существующий подход к публикации материалов: ученики видят только опубликованное.

## Что входит в MVP

- Анализ проекта и краткий `AI_TEACHER_IMPLEMENTATION_PLAN.md`.
- Раздел `ИИ-материалы` внутри существующей админки.
- Форма задания для ИИ: предмет, класс, тема, тип материала, инструкции.
- Серверная интеграция с OpenAI через переменные окружения.
- Mock-режим при отсутствии `OPENAI_API_KEY`, чтобы интерфейс можно было проверить локально.
- Сохранение результата генерации в БД.
- Ручное редактирование результата.
- Ручная публикация и снятие с публикации.
- Публичная страница опубликованных ИИ-материалов для учеников.
- Базовый DOCX-экспорт.
- Документация `AI_TEACHER_ASSISTANT_README.md`.
- Итоговый отчёт `AI_TEACHER_COMPLETION_REPORT.md`.

## Порядок реализации

- **Таск 1 — Архитектура, БД и каркас админки:** создать план внедрения, таблицы ИИ-материалов, модели, валидаторы, маршруты и страницы списка/создания/редактирования в существующей админке.
- **Таск 2 — Генерация материала через ИИ:** добавить серверный сервис OpenAI, mock-режим, запуск генерации, сохранение ответа, обработку ошибок и защиту API-ключа.
- **Таск 3 — Редактирование и публикация:** дать учителю редактировать результат, сохранять черновик, публиковать и снимать материал с публикации; показать опубликованные материалы ученикам.
- **Таск 4 — Экспорт и документация:** добавить DOCX-экспорт, базовые проверки, README по ИИ-помощнику и итоговый отчёт выполнения.

## Публичная часть

| Маршрут | Описание |
|---------|----------|
| `/ai-materials` | Список опубликованных ИИ-материалов для учеников. |
| `/ai-materials/{slug}` | Публичная страница одного опубликованного материала. |

## Админка

| Маршрут | Описание |
|---------|----------|
| `/admin/ai-materials` | Список ИИ-материалов учителя со статусами. |
| `/admin/ai-materials/create` | Форма задания для ИИ. |
| `/admin/ai-materials/{id}/edit` | Редактирование результата, сохранение черновика, публикация и снятие с публикации. |
| `/admin/ai-materials/{id}/generate` | POST-действие запуска генерации через серверный сервис. |
| `/admin/ai-materials/{id}/export-docx` | Скачать материал в DOCX. |

## База данных

| Таблица | Поля |
|---------|------|
| `ai_teaching_materials` | `id`, `title`, `slug`, `subject`, `class_title`, `topic`, `material_type`, `difficulty`, `estimated_duration`, `language`, `instructions`, `source_notes`, `generated_content`, `edited_content`, `status`, `generation_error`, `openai_response_id`, `model_used`, `prompt_version`, `published_at`, `created_by`, `created_at`, `updated_at` |
| `ai_material_files` | `id`, `material_id`, `file_type`, `original_name`, `stored_name`, `storage_path`, `mime_type`, `file_size`, `created_at` |

## Прототипы

**Страницы:**
- отдельного прототипа ИИ-помощника пока нет;
- `prototypes/admin/classes.html` → ориентир для админских списков;
- `prototypes/admin/submissions.html` → ориентир для списков со статусами;
- `prototypes/class.html` → ориентир для публичного просмотра материала;
- `prototypes/design-system/ui-design-system.html` → дизайн-система для форм, карточек и таблиц.

Вёрстку, CSS-классы и структуру разметки брать из существующих прототипов и дизайн-системы. Не создавать отдельный второй сайт и не заводить отдельный teacher-layout.

## Что НЕ входит в фазу

- Отдельный кабинет `/teacher/...`.
- Отдельная авторизация для ИИ-помощника.
- Второй layout или второе меню учителя.
- Полноценная база знаний с file search/vector store.
- PDF-экспорт, если для него потребуется отдельный внешний конвертер.
- История всех редакций материала.
- Расширенный аудит событий.
- Личный кабинет ученика.
- Автоматическая публикация материалов без ручного подтверждения учителя.
- Хранение или показ `OPENAI_API_KEY` в браузере, БД, логах или репозитории.

## Важные правила

- Следовать `AGENTS.md`.
- Следовать `.docs/architecture-rules.md`.
- Следовать `.docs/specs/` для PHP, HTML, CSS, JS.
- SQL только в models, логика не в templates.
- Все OpenAI-запросы выполнять только на сервере.
- Модель задавать через переменную окружения `OPENAI_MODEL`, ключ — через `OPENAI_API_KEY`.
- При отсутствии `OPENAI_API_KEY` реализовать mock-режим для локальной проверки интерфейса.
- ИИ не публикует материалы автоматически: публикация только вручную учителем.
- Черновики не должны быть доступны публично.
- Не трогать существующие функции сайта без явной необходимости.
- Не дублировать уже существующие admin-компоненты, если их можно переиспользовать.
