# Codex Work Modes

Используй эти режимы как короткие правила поведения Codex для разных типов задач.

---

## Planning Mode

Когда задача — спланировать продукт, фазу или TASK:

- Сначала прочитай `AGENTS.md`, `.docs/project-status.md` и релевантные документы из `.docs/product/`.
- Не меняй код приложения.
- Задавай вопросы только если без ответа нельзя составить точный план.
- Предлагай конкретный scope, файлы и проверяемые критерии.
- Результат фиксируй в Markdown-файлах `.docs/`, `.docs/_phases/` или `TASK.md`.

---

## Implementation Mode

Когда задача — реализовать `TASK.md`:

- Сначала прочитай `TASK.md`, `AGENTS.md`, `.docs/project-status.md` и релевантные specs.
- Проверь прототипы перед созданием страниц.
- Работай только в Scope, если нет явной необходимости выйти за него.
- Сохраняй архитектуру: controllers без SQL, models с PDO, templates без бизнес-логики.
- После правок проверь acceptance criteria и обнови статус проекта.

---

## Review Mode

Когда задача — проверить код:

- Сначала ищи баги, риски, регрессии и недостающие проверки.
- Указывай файл и строку, если возможно.
- Не переписывай код без запроса.
- Приоритет: безопасность, данные, архитектура, пользовательские сценарии, затем стиль.

---

## Bugfix Mode

Когда задача — исправить баг:

- Сначала воспроизведи или локализуй проблему.
- Найди минимальную причину.
- Исправляй точечно.
- Проверь исходный сценарий и хотя бы один близкий регрессионный сценарий.
- Если баг меняет правила или архитектурное решение — обнови документацию.

---

## Documentation Mode

Когда задача — обновить документацию:

- Не меняй поведение приложения.
- Синхронизируй связанные файлы: `readme.md`, `START_HERE.md`, `.docs/project-status.md`, `pipeline.md`.
- Пиши так, чтобы программист мог выполнить следующий шаг без устного объяснения.
- Избегай дублирования: если правило уже есть в `AGENTS.md`, ссылайся на него.
