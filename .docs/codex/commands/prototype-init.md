# prototype-init — Генерация HTML-прототипов

Ты разработчик UI. Твоя задача — предложить список страниц для прототипирования, согласовать его с разработчиком и сгенерировать HTML-прототипы на основе готовой дизайн-системы.

Общайся с разработчиком на **русском языке**.

---

## Шаг 1 — Проверь наличие дизайн-системы

Проверь что существует файл `prototypes/design-system/ui-design-system.html`.

Если файл отсутствует — скажи:

> Файл `prototypes/design-system/ui-design-system.html` не найден.
> Сначала используй инструкцию `.docs/codex/commands/design-system-init.md` чтобы сгенерировать дизайн-систему.

И **остановись**.

Если файл есть — переходи к шагу 2.

---

## Шаг 2 — Прочитай контекст проекта

Молча прочитай:

- `.docs/product/product-overview.md` — тип проекта и основной сценарий
- `.docs/product/features.md` — список запланированных фич
- `.docs/design/system/app-components.json` — специфичные компоненты проекта
- `.docs/design/direction.md` — визуальное направление

На основе этого определи какие страницы нужны для прототипирования.

---

## Шаг 3 — Предложи список страниц

**Лимит: максимум 8 страниц** (до 4 публичных + до 4 страниц админки).

Если проект подразумевает больше страниц — выбери самые важные, остальные упомяни как отложенные.

Предложи список в таком формате:

> Предлагаю следующие страницы для прототипирования:
>
> **Публичная часть:**
>
> - `home.html` — Главная (шапка, hero-блок, [секции из features], подвал)
> - `catalog.html` — Каталог (список карточек, фильтры)
> - `product.html` — Страница товара (галерея, описание, цена, кнопка в корзину)
> - `cart.html` — Корзина (список товаров, итого, оформление)
>
> **Админка:**
>
> - `admin/login.html` — Логин администратора
> - `admin/dashboard.html` — Дашборд (сводка, последние заказы)
> - `admin/products.html` — Список товаров (таблица, поиск, действия)
> - `admin/product-form.html` — Форма редактирования товара
>
> [Если есть отложенные]: Страницы вне этого набора (например: профиль, история заказов) — отложены, их можно добавить отдельно.
>
> Подходит? Или хочешь что-то изменить — добавить, убрать, заменить?

Дождись подтверждения или правок. После подтверждения — переходи к шагу 4.

## Шаг 4 — Сгенерируй прототипы

Сгенерируй все согласованные HTML-файлы. Для каждой страницы создай полноценный прототип с реальным контентом и стилями.

### Структура файлов

```
prototypes/
├── [page].html             ← страницы публичной части
├── admin/
│   └── [page].html         ← страницы админки
assets/
├── css/
│   ├── main.css        ← точка входа: @import всех файлов ниже
│   ├── base/
│   │   ├── reset.css   ← сброс браузерных стилей
│   │   ├── vars.css    ← CSS-переменные (цвета, типографика, отступы)
│   │   └── base.css    ← базовые стили: body, типографика, ссылки
│   ├── blocks/         ← BEM-блоки, один файл на блок
│   ├── sections/       ← стили секций страниц
│   └── utils/
│       └── utils.css   ← утилиты: .sr-only, .container и т.д.
├── js/
│   ├── main.js         ← точка входа: импортирует модули
│   └── modules/        ← JS-модули, один файл на функциональность
└── img/
	└── icons/          ← SVG-иконки
```

### Правила генерации

**HTML:**

- Следуй `.docs/specs/html.md`
- Каждая страница — полноценный HTML-документ с `<!DOCTYPE html>`
- Подключение CSS: `<link rel="stylesheet" href="../assets/css/main.css">` (или `../../assets/css/main.css` для страниц в `admin/`)
- Подключение JS: `<script type="module" src="../assets/js/main.js"></script>` (или `<script type="module" src="../../assets/js/main.js"></script>` для страниц в `admin/`)
- Семантические теги: `<header>`, `<main>`, `<nav>`, `<section>`, `<article>`, `<footer>`
- Все изображения: `<img>` с `alt`
- **Иерархия заголовков:** на каждой странице ровно один `<h1>` (главный смысловой заголовок страницы), далее `<h2>` для основных секций, `<h3>` для подразделов внутри секций. Пропускать уровни запрещено (нельзя `h1 → h3`). В компонентах (карточки, модалки) уровень заголовка определяется позицией компонента в общей иерархии страницы.

**CSS:**

- Следуй `.docs/specs/css.md`
- Используй CSS-переменные из `vars.css` — не хардкоди значения
- BEM-нейминг: `block__element`, `block--modifier`
- Один BEM-блок = один файл в `blocks/`
- Одна секция страницы = один файл в `sections/`
- Медиа-запросы вложены в селектор
- Адаптивность обязательна: от 320px до 1440px
- **Запрещены inline-стили** (`style="..."`) — абсолютно для всех элементов без исключений. Все стили — только в CSS-файлах. Нет исключений для «быстрых правок» или «уникальных случаев» в прототипах. Допустимы утилитарные стили из файла utils.css

**JS:**

- Следуй `.docs/specs/js.md`
- ES modules: `export function init...()`, инициализация в `main.js` внутри `DOMContentLoaded`
- Один модуль = один файл = одна ответственность
- Никакого jQuery, никаких глобальных переменных

**Контент:**

- Используй реалистичный placeholder-контент (не «Lorem ipsum»)
- Для изображений товаров используй `<div>` с фоновым цветом или SVG-плейсхолдер
- Все интерактивные элементы (модалки, табы, дропдауны) должны работать через JS-модули

## Адаптивность и сетка

### Брейкпоинты

| Точка | Ширина | Применение |
|---|---|---|
| Desktop | ≥ 1440px | Базовые стили, полный layout |
| Desktop small | ≥ 1200px | Чуть меньше заголовки, компактнее padding |
| Tablet (land) | ≤ 1024px | Чуть меньше заголовки, компактнее padding |
| Tablet (port) | ≤ 768px | Одна колонка, вертикальный stack |
| Small mobile | < 380px | Минимальные отступы, самые мелкие заголовки |

### Общие параметры

- **Минимальная поддерживаемая ширина:** 320px
- **Максимальная ширина контента:** 1440px

### Контейнер

- `max-width: 1440px`
- Горизонтальные отступы:
  - 24px — десктоп
  - 16px — планшет
  - 12px — мобильные устройства
