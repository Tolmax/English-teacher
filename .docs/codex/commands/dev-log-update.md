# dev-log-update — Запись в журнал разработки

Ты технический летописец проекта. Твоя задача — зафиксировать итоги текущей рабочей сессии в журнале `.docs/dev-log.md`.

Общайся с разработчиком на **русском языке**.

---

## Шаг 1 — Собери данные о завершённых фазах

Прочитай список файлов в `.docs/_phases/`.

Завершённые фазы — те, для которых существует файл `phase-N-report.md`.

Для каждой завершённой фазы прочитай её отчёт `phase-N-report.md` — раздел «Что сделано».

Также прочитай текущий `.docs/dev-log.md` (если существует) — чтобы не дублировать уже записанное.

---

## Шаг 2 — Задай один вопрос

Спроси:

> Что ещё добавить в запись помимо завершённых фаз?
> Например: исправления багов, обсуждения, решения по архитектуре, изменения в документации.
>
> Если добавить нечего — напиши «ок», запишу по фазам.

Дождись ответа и переходи к шагу 3.

---

## Шаг 3 — Допиши запись в dev-log.md

Если файл `.docs/dev-log.md` не существует — создай его с заголовком:

```markdown
# Dev Log

---
```

Затем **допиши в конец файла** новую запись в следующем формате:

```markdown
## YYYY-MM-DD — [короткий заголовок: суть сессии одной строкой]

**Фазы:** Phase N [, Phase N+1, ...]

- тезис 1
- тезис 2
- тезис 3
(3–6 пунктов, каждый — одно предложение)

**Детали:** `.docs/_phases/phase-N.md`

---
```

### Правила заполнения

- Заголовок — одна строка, суть всей сессии: что появилось или что стало работать
- Тезисы — только факты и результаты, без технических деталей реализации
- Пиши так, чтобы за 30 секунд было понятно что было сделано
- Не пересказывай детали из отчётов — только суть и результат
- Не дублируй то, что уже есть в `dev-log.md`
- Если в сессии были только исправления без завершённых фаз — опусти строку «Фазы» и «Детали»
- Если разработчик добавил что-то в шаге 2 — включи это в тезисы

---

## Шаг 4 — Подтверди результат

После записи выведи:

```
✅ Запись добавлена в .docs/dev-log.md

[Покажи добавленный текст целиком]

Сессия задокументирована. До следующей!
```
