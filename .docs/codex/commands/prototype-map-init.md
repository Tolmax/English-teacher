# prototype-map-init — Документирование прототипов

Ты аналитик проекта. Твоя задача — изучить все созданные HTML-прототипы и зафиксировать их структуру в файле `.docs/product/prototype-map.md`.

Это **обязательный шаг** перед использованием инструкции `.docs/codex/commands/spec-init.md`. Без него ИИ-агент не будет знать какие прототипы существуют и не сможет использовать их при реализации.

Общайся с разработчиком на **русском языке**.

---

## Шаг 1 — Проверь наличие прототипов

Проверь что в папке `prototypes/` есть HTML-файлы (кроме `ui-design-system.html`).

Если HTML-файлов нет — скажи:

> Прототипы не найдены в папке `prototypes/`.
> Сначала используй инструкцию `.docs/codex/commands/prototype-init.md` чтобы создать прототипы.

И **остановись**.

---

## Шаг 2 — Прочитай все прототипы

Прочитай **все** HTML-файлы из `prototypes/`:
- Все `.html` файлы в корне `prototypes/`
- Все `.html` файлы в `prototypes/admin/`
- Все `.html` файлы в `prototypes/design-system/`

Также проверь наличие папки `prototypes/unused/` — если она существует и содержит `.html` файлы, зафиксируй их отдельно (см. Шаг 3).

Также прочитай:
- Все CSS-файлы из `assets/css/blocks/` — они покажут какие переиспользуемые компоненты есть в проекте
- `.docs/product/product-overview.md` — для понимания контекста проекта

---

## Шаг 3 — Создай prototype-map.md

Создай файл `.docs/product/prototype-map.md`, полностью заменив его содержимое.

Структура файла:

```markdown
# Prototype Map

Прототипы — статические HTML/CSS страницы без бэкенда.
Расположены в папке `prototypes/`.
Используются как основа для вёрстки при реализации фаз.

---

## Страницы публичной части

### [Название страницы] — `prototypes/[файл].html`
**Назначение:** [что это за страница и для чего]
**Содержимое:**
- [перечисли реальные блоки и секции из HTML: шапка, hero, карточки, форма и т.д.]
**Переходы:**
- → `[файл].html` — [текст ссылки или кнопки]

---

## Страницы админки

### [Название страницы] — `prototypes/admin/[файл].html`
**Назначение:** [что это за страница]
**Содержимое:**
- [перечисли реальные блоки]
**Переходы:**
- → `admin/[файл].html` — [куда ведёт]

---

## Переиспользуемые компоненты

Компоненты из `assets/css/blocks/`:

- **[название блока]** (`blocks/[файл].css`) — [описание, на каких страницах используется]

---

## Черновики (не используются в разработке)

> Файлы в `prototypes/unused/` — это идеи и эксперименты. Они **не используются** при реализации фаз. При разработке брать разметку и стили только из прототипов выше.

### [Название] — `prototypes/unused/[файл].html`
**Статус:** черновик, не используется в разработке.
**Назначение:** [краткое описание идеи]
```

> Если папка `prototypes/unused/` отсутствует или пуста — секцию «Черновики» не добавляй.

### Правила заполнения

- Описывай содержимое конкретно — перечисляй реальные блоки из HTML, а не абстрактно
- Указывай переходы только те, что реально есть в `<a href="">` и кнопках
- Компоненты описывай на основе реальных CSS-классов из `blocks/`
- Не придумывай — только то что есть в файлах

---

После создания файла выведи:

Задокументировано:

Файл: .docs/product/prototype-map.md

Следующий шаг — обязательный:
