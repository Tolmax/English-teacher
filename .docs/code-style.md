# Code Style

## Общие правила

- писать просто и читаемо
- не создавать абстракции заранее
- не писать слишком большие функции
- один файл = одна ответственность

## PHP

- использовать функции и простые структуры
- ООП не использовать, кроме PDO и библиотек
- явные имена функций
- ранний return предпочтителен
- минимальная вложенность

## CSS

- только lowercase class names
- BEM naming only
- block\_\_element
- block--modifier

## JS

- native JS only
- без классов без необходимости
- небольшие модули
- не смешивать DOM-логику и бизнес-логику

## Naming

- понятные имена
- без сокращений кроме общепринятых
- одинаковый стиль по всему проекту

## Comments

- коммент перед каждой функцией с описанием того что она делает, её назначение.
- только там, где действительно нужно объяснение
- не комментировать очевидное

Общие правила:

- CSS-классы только в lowercase
- BEM: block, block\_\_element, block--modifier
- JS без классов, если это не оправдано
- PHP функции маленькие и одноназначенные
- Один файл — одна основная ответственность
- Не создавать “универсальные” абстракции заранее

Код стайл по каждой технологии описаны в отдельных файлах:

- `.docs/specs/css.md` — работа с CSS стилями
- `.docs/specs/php.md` — работа с PHP кодом
- `.docs/specs/html.md` — работа с HTML кодом (добавить, ARIA, доступность, семантические теги)
- `.docs/specs/js.md` — работа с JS кодом (каждая отдельная функциональность описана в отдельном файле как в модуле, экспортируется в основной main.js файл и подключается в него)
