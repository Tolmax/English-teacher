# AI Teacher Assistant README

## Боевой режим OpenAI API

Для реальной генерации задайте серверные переменные окружения:

```env
OPENAI_API_KEY=your_server_side_key
OPENAI_MODEL=gpt-5
```

API-ключ создаётся в OpenAI Platform: `https://platform.openai.com/api-keys`.
Перед реальной генерацией проверьте, что в аккаунте подключён биллинг и доступны лимиты API.

Если `OPENAI_MODEL` не задана или пуста, сервис использует безопасное значение по умолчанию `gpt-4.1-mini`. Бизнес-логика не привязана к конкретной модели.

Сервис `app/services/openai-teacher-assistant.php` выполняет серверный запрос к OpenAI Responses API, формирует отдельную системную инструкцию и пользовательское задание, ограничивает длину входных заметок учителя и сохраняет только полезный результат: текст материала, использованную модель и идентификатор ответа.

Учитель может увидеть понятные ошибки:
- неверный или недоступный `OPENAI_API_KEY`;
- недоступная модель из `OPENAI_MODEL`;
- лимит запросов или баланса;
- сетевой сбой, DNS/SSL-проблема или тайм-аут;
- пустой ответ;
- некорректный формат ответа;
- отказ модели выполнить запрос.

Сырой ответ API и значение `OPENAI_API_KEY` не выводятся в HTML, не сохраняются в БД и не должны попадать в логи или документацию. При ошибке последний отредактированный материал не очищается: сохраняется только безопасное сообщение в `generation_error`.

Файл `.env.example` содержит пример переменных из рекомендаций раздела 7 исходного задания, включая будущие настройки file search/vector store. В текущем MVP file search и vector store не реализуются.

### Локальная проверка через PowerShell

Live Server из VS Code для боевого режима не подходит: он обслуживает статические файлы и не запускает PHP-приложение с нужными переменными окружения.

Для проверки используйте встроенный PHP-сервер:

```powershell
cd "c:\Users\Пресс-служба\OneDrive\Рабочий стол\Codex\english"

$env:OPENAI_API_KEY="your_server_side_key"
$env:OPENAI_MODEL="gpt-4.1-mini"

php -r "echo strlen(getenv('OPENAI_API_KEY'));"
php -S 127.0.0.1:8010
```

Команда `php -r "echo strlen(getenv('OPENAI_API_KEY'));"` должна вывести число больше нуля. Сам ключ выводить, копировать в чат или записывать в файлы проекта нельзя.

После запуска открывайте именно адрес PHP-сервера:

```text
http://127.0.0.1:8010/admin/login
http://127.0.0.1:8010/admin/ai-materials
```

Если страница всё ещё показывает mock-режим, проверьте, что:
- сайт открыт не через Live Server и не через порт `5500`;
- PHP-сервер запущен в том же PowerShell-окне, где задан `OPENAI_API_KEY`;
- в окне PHP-сервера появляются запросы к `/admin/ai-materials`.

### XAMPP/Apache

Для Apache/XAMPP переменные, заданные через `$env:...` в PowerShell, обычно не попадают в уже запущенный Apache. В этом случае `OPENAI_API_KEY` и `OPENAI_MODEL` нужно задать на уровне Windows или конфигурации Apache, затем полностью перезапустить Apache.

Для первой проверки проще использовать `php -S` из PowerShell, как показано выше.

### Как понять результат проверки

- Сообщение `Сейчас работает mock-режим: OPENAI_API_KEY не задан на сервере.` означает, что PHP-процесс не видит ключ.
- Сообщение про неверный ключ означает, что ключ дошёл до OpenAI, но был отклонён.
- Сообщение про лимит запросов или баланса означает, что серверный запрос до OpenAI дошёл, но аккаунт/проект OpenAI ограничен по балансу, тарифу или rate limit.

При ошибке лимита проверьте:
- биллинг OpenAI Platform;
- лимиты организации/проекта;
- что ключ создан в проекте, где доступен биллинг;
- модель `OPENAI_MODEL`, для теста лучше использовать `gpt-4.1-mini`.

## Что реализовано

ИИ-помощник учителя встроен в существующую админку сайта, без отдельного `/teacher`-кабинета.

Учитель может:
- войти через `/admin/login`;
- открыть раздел `/admin/ai-materials`;
- создать черновик ИИ-материала;
- сгенерировать текст через OpenAI или mock-режим без API-ключа;
- отредактировать `edited_content`;
- вручную опубликовать или снять материал с публикации;
- скачать материал в DOCX;
- показать ученикам опубликованные материалы на `/ai-materials` и в блоке "Материалы к уроку" выбранного класса.

## Библиотека и архив ИИ-материалов

Phase 5 развивает ИИ-помощника как библиотеку повторно используемых материалов. Сгенерированные тесты, рабочие листы и объяснения не нужно удалять после окончания учебного года: у материала есть метаданные `Учебный год`, `Период` и `Теги`, которые помогают позже найти нужную заготовку.

Архивация в библиотеке должна сохранять `generated_content` и `edited_content`. Материал можно будет убрать из актуальной выдачи, но оставить для следующего поколения учеников. Физическое удаление не является основным сценарием.

В Task 1 Phase 5 добавлена основа библиотеки:
- `school_year` — учебный год или сезон;
- `period` — четверть, месяц, раздел учебника или другой период;
- `tags` — свободные теги через запятую;
- `archived_at` — будущая дата архивации;
- `source_material_id` — будущая ссылка на исходный материал при создании копии.

В Task 2 Phase 5 добавлена рабочая библиотека в `/admin/ai-materials`:
- поиск по названию, теме, тегам и тексту материала;
- фильтры по классу, типу материала, статусу и учебному году;
- режимы просмотра "актуальные", "архив" и "все";
- архивирование через POST-действие `/admin/ai-materials/{id}/archive`;
- восстановление через POST-действие `/admin/ai-materials/{id}/restore`;
- защита публичной части: архивные материалы не видны ученикам на `/ai-materials`, `/ai-materials/{slug}` и `/class/{slug}`.

В Task 3 Phase 5 добавлено повторное использование материалов:
- в списке и на странице редактирования есть действие "Создать копию";
- GET `/admin/ai-materials/{id}/duplicate` открывает форму адаптации копии;
- учитель может изменить название, класс, тему, учебный год, период и теги;
- новая запись получает новый `slug` и `source_material_id` со ссылкой на оригинал;
- копия сохраняет текст, инструкцию, заметки, тип, уровень и связанные файловые записи;
- публикация не копируется: новая версия остаётся непубличной до ручной проверки и публикации;
- оригинальный материал при копировании не меняется.

## Архитектура

Используется текущий стек проекта: PHP 8.x, SQLite + PDO, MVC без фреймворка, `.tpl` шаблоны и существующая админская авторизация.

Основные файлы:
- `app/models/ai-teaching-material.php` — SQL для ИИ-материалов;
- `app/models/ai-material-file.php` — SQL для связанных файлов;
- `app/services/openai-teacher-assistant.php` — генерация OpenAI/mock;
- `app/services/docx-export.php` — сборка DOCX;
- `app/controllers/admin/ai-materials/` — админские действия;
- `app/controllers/ai-materials/` — публичный просмотр.

## Переменные окружения

Для реальной генерации нужен серверный API-ключ:

```env
OPENAI_API_KEY=your_server_side_key
OPENAI_MODEL=gpt-4.1-mini
```

Если `OPENAI_API_KEY` не задан, сервис работает в mock-режиме и создаёт тестовый материал без внешнего запроса.

Важно:
- ключ не передаётся в браузер;
- ключ не хранится в БД;
- ключ не должен попадать в логи или репозиторий.

## Маршруты

Админка:
### Как понять режим генерации

Текущий режим можно проверить прямо в админке:
- на странице `/admin/ai-materials`;
- на форме `/admin/ai-materials/create`;
- на форме `/admin/ai-materials/{id}/edit`.

Если показан режим `mock`, значит сервер не получил `OPENAI_API_KEY`, поэтому генерация возвращает тестовый mock-материал для проверки интерфейса. Если показан режим `OpenAI API`, ключ задан на сервере, но его значение не выводится в HTML и не сохраняется в БД.

Маршруты админки:
- `/admin/ai-materials`
- `/admin/ai-materials/create`
- `/admin/ai-materials/{id}/edit`
- `/admin/ai-materials/{id}/generate`
- `/admin/ai-materials/{id}/publish`
- `/admin/ai-materials/{id}/unpublish`
- `/admin/ai-materials/{id}/export-docx`

Публичная часть:
- `/ai-materials`
- `/ai-materials/{slug}`
- `/class/{slug}` — опубликованные ИИ-материалы выбранного класса встроены в блок "Материалы к уроку".

Публично доступны только материалы со статусом `published`, заполненным `published_at` и непустым `edited_content`.

## DOCX-экспорт

DOCX создаётся на лету через `ZipArchive` без внешних библиотек. Если `edited_content` пустой, экспорт не выполняется, а учитель возвращается на страницу редактирования с понятной ошибкой.

## Ограничения MVP

В текущий MVP не входят PDF-экспорт, OpenAI file search, vector store, история редакций, расширенный аудит, личный кабинет ученика и отдельный `/teacher`-кабинет.

## База знаний в генерации

Phase 6 добавляет локальное использование выбранных источников базы знаний при генерации ИИ-материала.

- Сервис `app/services/ai-knowledge-context.php` готовит ограниченный текстовый контекст из активных неархивных источников, связанных с материалом.
- Сервис `app/services/openai-teacher-assistant.php` добавляет блок "Источники базы знаний" в prompt только если контекст не пустой.
- Mock-режим без `OPENAI_API_KEY` остаётся рабочим и показывает в результате, какие источники были учтены.
- OpenAI-режим получает только подготовленный текстовый контекст, без API-ключей и сырых технических логов.
- Если источники не выбраны, генерация идёт по прежнему сценарию.

Это ещё не OpenAI file search/vector store: поля `openai_file_id` и `vector_store_id` сохранены как задел для следующего этапа.
