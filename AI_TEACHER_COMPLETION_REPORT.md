## Phase 5 Task 3 — Повторное использование материала

Реализовано:
- добавлено действие "Создать копию" в списке `/admin/ai-materials` и на странице редактирования материала;
- добавлен маршрут GET/POST `/admin/ai-materials/{id}/duplicate`;
- создана форма адаптации копии с полями: название, класс, тема, учебный год, период и теги;
- копия получает новый уникальный `slug` и `source_material_id` со ссылкой на оригинал;
- копия переносит тип, предмет, уровень, время, язык, инструкции, заметки, `generated_content`, `edited_content`, модель и response id;
- связанные записи `ai_material_files` копируются на новый материал без физического дублирования файла;
- копия не наследует публикацию и архив: `published_at` и `archived_at` пустые, статус `ready` при наличии текста или `draft`, если текста нет;
- оригинальный материал при копировании не изменяется.

Проверено:
- `php -l` для изменённых PHP/TPL-файлов;
- временный SQLite-сценарий: создание исходного материала, добавление файловой записи, создание копии, проверка нового slug, `source_material_id`, статуса, контента, файловой записи и неизменности оригинала.

## Phase 4 Task 3 — Проверка боевого сценария и документация

Реализовано:
- обновлена инструкция `AI_TEACHER_ASSISTANT_README.md` по безопасному подключению `OPENAI_API_KEY`;
- описан способ получения ключа в OpenAI Platform без сохранения ключа в репозитории;
- добавлен пошаговый локальный запуск через PowerShell и `php -S`;
- зафиксировано, что Live Server не подходит для проверки PHP/OpenAI-режима;
- добавлена проверка `php -r "echo strlen(getenv('OPENAI_API_KEY'));"`, чтобы убедиться, что PHP видит ключ;
- описан отдельный сценарий для XAMPP/Apache: переменные окружения задаются на уровне сервера или Windows, после чего Apache нужно перезапустить;
- описаны различия между mock-режимом, ошибкой неверного ключа и ошибкой лимита/баланса.

Проверено вручную вместе с пользователем:
- без серверного `OPENAI_API_KEY` админка показывает mock-режим;
- при запуске через Live Server ключ не попадает в PHP-приложение, поэтому mock-режим сохраняется;
- при запуске через `php -S` из того же PowerShell, где задан ключ, PHP видит `OPENAI_API_KEY`;
- команда проверки длины ключа вернула `164`, то есть переменная окружения была доступна PHP;
- после запуска сайта на новом PHP-порту mock-режим выключился, а запрос дошёл до OpenAI API;
- OpenAI API вернул безопасно обработанную ошибку лимита запросов или баланса.

Итог проверки: серверная интеграция с OpenAI подключается корректно, ключ не выводится наружу, а ошибка лимита/баланса относится к настройкам аккаунта OpenAI Platform. Успешный реальный ответ с сохранением материала пока не подтверждён, потому что текущий аккаунт/проект OpenAI вернул лимит или недостаток баланса.

Что осталось сделать вручную:
- проверить биллинг OpenAI Platform;
- проверить лимиты организации/проекта;
- убедиться, что ключ создан в проекте с доступным биллингом;
- повторить генерацию с `OPENAI_MODEL=gpt-4.1-mini`;
- после успешного ответа проверить редактирование, публикацию, отображение материала в классе и DOCX-экспорт.

## Проверки

Проверены сценарии:

- mock-генерация работает без `OPENAI_API_KEY`;
- результат генерации сохраняется в `generated_content` и `edited_content`;

- неопубликованный материал публично возвращает 404;

- DOCX содержит заголовок, метаданные и текст материала;
- спецсимволы в DOCX экранируются для XML;
- временные DOCX-файлы не остаются в `storage/temp`;
- несуществующий экспорт возвращает 404;
- изменённые PHP/TPL-файлы проходят `php -l`.
