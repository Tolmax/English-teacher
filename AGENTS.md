## Tech Stack

**Используем:**
- PHP 8.x, SQLite, PDO
- MVC без фреймворка
- Шаблоны `.tpl` (чистый PHP, функция `renderTemplate()`)
- Нативный JS (ES modules)
- CSS + BEM (без препроцессоров)
- Editor.js — для rich-text контента
- GD library — для обработки изображений

**Не используем — никогда:**
- React, Vue и любые JS-фреймворки
- Tailwind, Bootstrap, SCSS
- jQuery
- ORM
- MySQL (SQLite на всех этапах)
- Внешние UI-библиотеки
- CDN (JS-библиотеки скачиваются локально)
- Сложный ООП в бизнес-логике

**В дизайне не используем — никогда:**
- Glassmorphism (размытые стёкла, backdrop-filter)
- Сложные анимации и transition-эффекты
- Перегруженные градиенты
- Неоновые свечения и glow-эффекты
- Тёмные фоны с яркими акцентами в стиле "SaaS dashboard"
- Мелкий текст (базовый размер не менее 16px)
- Карточки с heavy shadow и border-radius > 16px
- Декоративные blob-формы и абстрактные SVG-фигуры на фоне

## Архитектура

### Структура проекта

```text
app/
  controllers/   — контроллеры (PHP-файлы, не классы)
  models/        — модели (функции, не классы)
  services/      — сервисы (файлы, изображения, email)
  validators/    — валидаторы входных данных
  core/          — роутер, рендерер, хелперы, db, logger
  helpers/       — вспомогательные функции
config/
  app.php        — константы ROOT и HOST
  database.php   — подключение к БД
  routes.php     — маршруты
templates/
  partials/      — header, footer
  pages/         — страницы
  components/    — переиспользуемые блоки
```

### Константы

- `ROOT` — абсолютный путь к корню проекта (для файловых путей)
- `HOST` — URL сайта с trailing slash (для ссылок в коде)
- Ссылки в контенте БД — полный URL (`https://...`)

## Правила по слоям

### Контроллеры

> **Обязательно:** перед созданием любого контроллера читай `.docs/app/ARCHITECTURE.md` — там описаны правила структуры, роутинга, разбивки на файлы и антипаттерны. Стиль PHP-кода — `.docs/specs/php.md`.

- Один файл — одно действие (list, create, edit, delete — каждое в отдельном файле)
- Роутинг строится цепочкой `index.php`-диспетчеров по уровням URL
- Валидация — только через функции из `app/validators/`, не inline в контроллере
- Сервисная логика (загрузка файлов, email и т.п.) — только через `app/services/`
- Файлы, не классы
- Принимают запрос → вызывают модель/сервис → `renderTemplate()` или `redirectTo()`
- Никакого SQL
- POST-действия всегда заканчиваются `redirectTo()` (PRG-паттерн)
- Всегда `trim()` для строк из `$_POST`, `(int)` для чисел
- Email и критические данные — из БД, не из `$_POST`

### Модели

- Файлы с глобальными функциями, не классы
- Только SQL через PDO с параметрами — никакой конкатенации
- `LIMIT`/`OFFSET` всегда через `bindValue(..., PDO::PARAM_INT)`
- Возвращают данные, не рендерят HTML
- Не вызывают сервисы и не делают редиректы

### Шаблоны (`.tpl`)

> **Обязательно:** при работе с шаблонами читай `.docs/specs/html.md`.

- Весь вывод строк через `e()` — `htmlspecialchars()` обёртка
- Числа — через `(int)` без `e()`
- Цены — через `formatPrice()`
- Ссылки — через `HOST`
- Пути к `include` — через `ROOT`
- Никакого SQL, никаких редиректов, никаких вызовов сервисов

### CSS

> **Обязательно:** при работе со стилями читай `.docs/specs/css.md`.

- Только BEM: `block__element`, `block--modifier`
- Структура: `base/` → `blocks/` → `sections/` → `utils/`
- Медиа-запросы — вложены в селектор
- Никакого инлайн-стиля кроме уникальных случаев

### JS

> **Обязательно:** при работе со скриптами читай `.docs/specs/js.md`.

- ES modules (`import`/`export`)
- Один модуль = один файл в `assets/js/modules/`
- Точка входа — `assets/js/main.js`
- Никакого jQuery, никаких глобальных переменных

## Безопасность

- Все строки из БД и `$_POST`/`$_GET` в шаблоне — через `e()`
- Числовые ID из URL — через `requireNumericId()`
- Проверка существования записи — через `requireFound()`
- Защищённые роуты — `requireAuth()` или `requireUser()` в начале контроллера

## Прототипы

В папке `prototypes/` находятся готовые HTML-прототипы всех страниц и дизайн-система проекта.

**При реализации любой страницы — сначала проверь прототип:**
- Если прототип существует — бери разметку, CSS-классы и структуру напрямую оттуда
- Не изобретай новую разметку и не придумывай CSS-классы, если прототип есть
- Дизайн-система: `prototypes/design-system/ui-design-system.html`

**CSS, JS и изображения прототипов** находятся в `assets/`:
- `assets/css/` — стили (уже разбиты по BEM: base/, blocks/, sections/, utils/)
- `assets/js/` — JS-модули
- `assets/img/` — изображения
